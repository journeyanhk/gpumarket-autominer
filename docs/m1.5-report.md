# PRL × 租卡挖矿：M1.5 实验报告（v1，2026-10-27）

> 范围：2026-10-26 18:26 → 2026-10-27 15:00（北京），约 20.5 小时，36 个机时，净投入 $19.90。
> 目的不是盈利，是把「能不能做」拆成六个可测量的数。第 7 条（两池计酬）实验进行中。

## 0. 一句话结论

**今天在任何场地租卡挖 PRL 都是负收益**（最好的 vast 竞价也在盈亏线之上 8–33%）；但**整条链路已经打通**，
且最关键的未知量不是租金，而是「矿池按多少算力给你计酬」——这一条正在用两池对照实验定性。

## 1. 收入密度：三个源差 21%，必须用保守源

| 源 | 全网算力 | 出块 | $/TH·天 |
|---|---:|---:|---:|
| Pearlhash | 91.3 EH/s | 152.1s | 0.0240 |
| **Kryptex（保守）** | 88.5 EH/s | 194.0s | **0.0196** |
| WhatToMine | 88.5 EH/s | 154.0s | 0.0246 |

**含义**：12% 的 ROI 门槛正好落在这个分歧区间里——按乐观源算是 +24% 的机器，按保守源是 −2%。
引擎已改为 `revenueSource=min`，且**决策用 6 小时滚动均值**（瞬时值每小时抖 3–5%，会让"今天能不能租"随刷新而变）。

## 2. realizedFactor：矿池口径的 0.99 是同义反复

PPS+ 按份额付钱，而矿池报的算力也是从份额换算的，同源相除必然 ≈1，**不含任何信息**。
真正的分母是「我们付钱买来的本地算力」：

| 机器 | 矿工自报 | 矿池计酬 | 折扣 |
|---|---:|---:|---:|
| 1×3090（按需，CZ） | 136.9 TH/s | 75.5–98.4 TH/s | **0.55–0.72** |
| 1×4070S（按需，Kryptex） | 118.4 TH/s | 80 → 190 TH/s（预热后追平） | 0.68 → 1.0 |

**含义**：按本地算力重算，Kryptex 段 realizedFactor ≈ **0.71**，不是 0.99。
但 4070S 那台的教训是：**预热期的 30 分钟均值会低报，必须先跑满 30 分钟再判断**。
到底"少给"还是"没计"，两池实验（第 7 条）给答案。

## 3. 竞价存活：不是"5 分钟必死"，而是双峰

25 个样本：中位 ~18 分钟，但分布明显两簇——

- **5 台死在出算力之前**（5–6 分钟）：镜像还没拉完就被收回；
- **10 台活到 18–130 分钟**：最长那台 4060 跑了 130 分钟。

**含义**：活过 45 分钟的概率约 **24%**。所以"spot 撑不过 5 分钟"是错的，"spot 稳定"也是错的；
正确的用法是把它当**概率事件**：出价 = 入场×1.25 且不超利润上限，被顶先改价（每实例每小时 ≤3 次），改不动才销毁。

## 4. 按需是结构性亏损，不是"贵一点"

3090 按需实付 **$0.1598/h**，当日盈亏线 **$0.0885/h**——即使算力 100% 计酬也是 **−45%**。

**含义**：按需只适合做「测量锚点」，且必须显式接受负 ROI（我们给它加了 `pinned`，不参与止损淘汰）。
把它当"稳定产出"是错的。

## 6. 变现链路：两段已通，第三段卡在交易所下限

| 环节 | 状态 | 数据 |
|---|---|---|
| 矿池 → 钱包 | ✅ 已通则 | Kryptex 打款 1.03357554 PRL，手续费 **0**，txid `bbb18030…f192a59` |
| 钱包 → 交易所 | ✅ 已通则（费用高） | Pearl 钱包 **固定 0.1 PRL** 发送费 + 0.0000015 网络费；1 PRL 时占 **9.7%** |
| 交易所 → 卖出 | ⏸ 卡下限 | Gate `PEARL_USDT` 最小下单 **3 USDT**（≈1.70 PRL），当前只有 0.93 |
| 对冲 → 平仓 | 工具就绪 | Lighter PRL 永续 `market_id=4097`，**taker/maker 0 手续费**，最小 5 PRL |

**含义**：
- **归集阈值定为 30 PRL**（固定费占比 0.33%），这不是拍脑袋：钱包固定费与交易所最小额各自独立指向同一个量级；
- 卖出按批（≥10 PRL）摊薄 Gate 0.2% + 点差 0.13%；
- **Gate 的 `PEARL` 是 Pearl（chain PEARL），`PRL` 是 Perle（chain SOL）**——两次独立验证，脚本已加硬断言。

## 9. 对下一步的含义

1. **归因前不租生产机**：现在唯一在跑的是实验机；缺口性质（被拒 vs 没计）没定性前，扩大规模等于放大未知；
2. **对冲只覆盖真实库存 + 3 天预期产出**：当前 5.7 PRL 空单对库存 2.19 PRL，多出的是裸空，
   已设触发：PRL > $2.0 或账户缓冲 < 200% 名义 → 减到库存量；
3. **门槛保持 20%**：降门槛只是用亏损买数据，而数据已经能从实验里拿；
4. **下次要验的**：镜像替换（部署 2.9 分钟里 2.2 分钟是拉镜像）、WildRig 的 API 采样、
   以及 Pearlhash 是否能给出可信的逐 worker 计酬。
