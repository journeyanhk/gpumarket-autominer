# 变现管道成本（PRL → USDT）

> 口径（2026-10-28 定）：报告固定三列 —— **已到账 / 已确认 / 待结算**；
> 净额 = （已到账 + 已确认）× 卖出时价 − 台账 spend。待结算单列，不进净额。

## 第一笔完整闭环（2026-10-28）

| 段 | 动作 | 数量 / 费率 | 价值（$） | 耗时 |
|---|---|---|---|---|
| 1 | Pearlhash 池内 → 链上（Auto Payment） | 1.09589429 PRL，**池费 0** | — | 过 1 PRL 后 ~1h47m 自动打款 |
| 2 | Pearl 钱包 → Gate 充值地址 | 发 1.09589429，**固定费 0.1 PRL**，到账 0.9959 | −0.166（占 8.7%） | ≈30 分钟 |
| 3 | Gate 卖出 `PEARL_USDT` | 1.9 PRL @ **1.6633**（IOC 吃买一） | +3.16027，taker 费 **0.00316**（0.1%） | 即时 |
| 4 | Lighter 平对冲（reduce-only 市价） | 1.9 PRL @ 约 1.67（滑点上限 0.5%） | 对冲端实现约 **+0.20** | 即时 |

**结论与坑**

- 单笔金额 1 PRL 量级时，**固定费 0.1 PRL 占 8.7–10%**；归集到 2 PRL 以上再发才是正解（阈值 ≥2 PRL）。
- Gate `PEARL_USDT` 三大约束：`min_base 0.1`、**`min_quote 3 USDT`**（按现价需 ≥1.80 PRL）、数量精度 **0.1**。
  低于 3 USDT 根本不能下单，所以 0.93 PRL 在 Gate 里放了一整天。
- Gate 的卖一档可能有巨墙（实测 613 PRL @ 1.6654），**挂卖一等于排队到天荒地老**；
  买一档 12.3 PRL 足够吃，于是选择 IOC 贴买一（价差成本 ~0.13%，远小于等 30 分钟的行情风险）。
- 残余 0.03 PRL 卡在 `min_base 0.1` 以下，只能等下次归集。
- 脚本侧两个坑（已修）：`floorSize` 的浮点误差会把 1.9 算成 1.8（少卖一手）；
  `--size` 显式指定时不该再被"买一档 20%"的防打穿上限压到 min_quote 以下。

## 第二轮闭环（2026-10-28 晚）与摩擦率模型

| 段 | 数值 |
|---|---|
| Pearlhash 出金 | 1.09589429 PRL（池费 0，`Auto Payment`，过线后约 1h47m） |
| 钱包 → Gate | 发 1.09589429，固定费 **0.1 PRL**，到账 0.9959（≈30 分钟） |
| Gate 卖出 | 1.9 PRL @ **1.6633** = 3.16027 USDT，taker **0.00316 USDT（0.1%）** |
| Lighter 平仓 | 1.9 PRL reduce-only，滑点上限 0.5%，与 Gate 成交价基差 < 0.5% |

**摩擦率 = 固定费 0.1 PRL ÷ 单批数量 + Gate taker + 滑点**

| 单批数量 | 固定费占比 | Gate taker | 总摩擦（估） |
|---|---|---|---|
| 2 PRL | **5.0%** | 0.1% | ≈ **5.2%** |
| 10 PRL | 1.0% | 0.1% | ≈ 1.2% |
| **30 PRL** | **0.33%** | 0.1% | ≈ **0.55%** |

**对门槛的含义**：名义 ROI 必须覆盖「目标 + 摩擦」。

- 2 PRL 批次：20% 目标 → 实际需要 **25.2%** 名义；
- 30 PRL 批次：20% 目标 → 实际需要 20.6% 名义，**15% 目标时只需 15.6%，仍高于盈亏线**。

所以：**批次 <10 PRL 时维持 20% 门槛；单批稳定 ≥30 PRL 后才把门槛降到 15%**——否则降门槛只是在放大固定费的相对损耗。
